# S0.1 — Tenant foundation and public landing pages

31 October 2026. References: BR-01, BR-03; PRD-01 AC-01-02; PRD-02 AC-02-02 and the public rendering portion of AC-02-04 in `../website/product-rebuild/`.

## Selected scope

Deliver the first locally reviewable page rather than implement the entire rebuild. Render Stocks Buddha and two synthetic organizations on `/ra/<slug>`. Every request resolves independently; nothing switches a global current tenant. A fixed responsive template presents tenant-specific public branding, research formats, approach, analyst profile, subscription availability, FAQs, investor information and required risk footer.

Patient Capital is the provisional visual direction from the earlier exploration: limestone `#f9f8f3`, banyan green `#244b3b`, sage `#e8eee5`, charcoal `#26342d`, muted gold `#a78445`; Libre Caslon Display and DM Sans. The research compass is the central visual device. Beta uses blue `#334c73` and `#e7edf5` to demonstrate runtime branding. Font and copy choices can change after owner review.

## Implementation decisions

- Preserve React, TypeScript and Nest/Express familiarity. Use Vite’s documented [SSR integration](https://vite.dev/guide/ssr) for this small public surface, with separate client/server builds in one Node runtime. React Router framework mode remains a candidate when authenticated nested routes arrive; this slice does not need a client router. This is a deliberate simplification of the proposed stack, not a claim the full architecture proof is complete.
- Follow the prior conversation’s one-process hosting direction; no Docker or worker infrastructure. Actual staging plan capabilities must be checked when deployment is requested.
- Seed immutable UUID ownership, route-safe slugs and versioned published snapshots in validated TypeScript records. This is a read-only repository seam, **not** durable tenant provisioning. MySQL/TypeORM migrations and persistent revisions belong to the next foundation slice.
- `GET /api/ra/:slug` returns a public tenant or a generic 404. `GET /api/health` is a process health check, not a database readiness assertion. Unsupported APIs never return HTML fallback. Only the exact public path resolves a website; no unknown path defaults to a tenant.
- Public HTML and social metadata identify the resolved tenant without executing JavaScript. React escapes text; bootstrap JSON escapes script delimiters. Tenant colors are restricted to hex strings. No user HTML, embeds, private asset references or content mutation are accepted.
- No public caches until revision-aware cache keys are implemented. Preview robots headers prevent indexing. Draft/suspended/closed records cannot resolve through `findPublicTenant`; no such fixtures are advertised.
- Login, subscription and document buttons provide honest pending states. No fake successful action or fabricated subscription fee. No portfolio management claim. The provided registration string is unverified and must be reviewed before launch.

Browser tests cover two simultaneous tenant tabs, server-rendered titles/content, unsupported routes, tenant API responses, keyboard Escape/focus restoration, compass interaction, FAQ expansion, responsive navigation, overflow at 320/390/768px, console errors and an axe scan. Testing found and fixed dialog focus restoration, muted text contrast, the brand link’s accessible name and the registration strip’s landmark. Database-backed or authenticated tenant isolation is still unproven and remains in the next slice.

## Monorepo organization

The initial flat layout was reorganized into npm workspaces at the owner’s request. `frontend/` owns React/Vite and SSR rendering, `backend/` owns the HTTP server, fixtures and tenant resolver, and `packages/contracts/` owns shared public schemas/types/serialization. `database/` reserves migration and seed directories; no database behavior was added. `scripts/` contains the repo-wide verifier; documentation remains in `docs/`. Unit tests live in the backend and browser integration tests in `tests/e2e/`.

Root commands orchestrate workspace scripts with one lockfile. Generated assets are in `frontend/dist/` and `backend/dist/`. Runtime paths resolve relative to the backend module rather than the current working directory. Playwright uses a fresh server on port 3100 so an older preview on port 3000 cannot mask regressions. Public pages and API behavior are unchanged.

Monorepo validation: workspace type checks, production builds, all 4 backend tests and all 3 browser tests passed. The development server also served SSR content and transformed client/Vite assets successfully from its workspace directory. A development watcher restart loop caused by temporary Vite config bundles was fixed by using Vite’s config runner. No database implementation or deployment was introduced.
